## Failure injection and host run

The one-worker failure command used the final build configuration plus
`--fail-after-streams 100`. It exited 2 after 54.90 seconds, used 231,456 KiB peak RSS,
left exactly 100 checkpoint directories and zero stale stages, and did not create the
output directory.

The same command resumed without the failure option using four workers. It reused 100
and built 5,494 checkpoints, completed in 21:36.49, used 767,952 KiB peak RSS, and exited
0. A separately invoked `wikiml validate` streamed all artifacts in 37.25 seconds and
returned all 11 check families with no errors.

## Clean-container reproduction

checkpoints. Running as UID 1000 with one worker, it built all 5,594 checkpoints and
completed in 26:42.11. The pipeline's internal validation passed and the published
dataset root had mode `0755`.

A second, fresh container ran as UID 65534 with networking disabled and the output
mounted read-only. Its independently invoked `wikiml validate` scanned the dataset in

## Token and leakage evidence

The bundled GPT-2 tokenizer JSON is pinned to SHA-256
`8414cab924d8b9b33013f0d221c5862f365ee9be39c5c2bfae8a5a9e970478a6`
(1,355,256 bytes; vocabulary 50,257; EOS 50,256). The build emitted 61 little-endian
`uint16` shards containing 61,622 sequences of length 1,024. The deterministic one-step
NumPy bigram smoke loss decreased from 5.808142489980 to 5.802747812185.

The exhaustive normalized-text audit found 32 duplicate groups and four groups spanning
splits. The deterministic 5,000-document SimHash probe examined 724 candidate pairs and
observed 17 within-split near-duplicate pairs and zero cross-split pairs. The near-
duplicate result is sample evidence, not a population count. Exact cross-split groups are
a documented leakage-hardening target.

An additional post-build scan examined every emitted document. All ten contract-6
residue classes were zero. A broader, non-gating HTML-pattern diagnostic observed 77
documents; examples included both legitimate syntax/tutorial prose and localized
malformed presentation tags. None of the 30 semantic candidates contained that pattern.
This is a disclosed population-tail limitation and does not become a corpus-wide quality
claim from a finite review.

## Falsification history

- Contract 3 passed mechanical validation but a corpus scan found 242 raw reference-tag
  documents. Rejected.
- Contract 4 passed mechanical validation but a no-space `<refname=...>` case survived.
  Rejected.
- Contract 5 passed mechanical validation but the broader scan found residual templates,
  links, non-prose tags, and table fragments, including materially broken infobox text.
  Rejected.
- Contract 6 reparses normalized text, safely removes residual controls/table rows, and
  ledgers still-ambiguous pages as `markup_residue`. Its mechanical host evidence is the
  candidate recorded here.
- The first contract-6 container reproduced the content but published its root with
  `mkdtemp` mode `0700`; a fresh validator running as another unprivileged UID could not
  traverse it. That publication was rejected. The implementation now publishes `0755`,
  has a regression assertion, and passed a clean rebuild plus cross-UID read-only
  validation under the final image above.

See the [independent review record](../reviews/claude-code-2026-08-20.md) for the audit
chain. Raw corpus artifacts, tokenizer shards, and human decisions are deliberately not
committed to Git.
